# Loop Calendar

Командный календарь для [Loop](https://loop.ru), управляемый через slash-команду `/cal`.

Loop Calendar позволяет команде отмечать удалённую работу, отпуска, отгулы, больничные и встречи, а также просматривать общий календарь и собственные события прямо в Loop.

**SQLite является единственным источником истины.** Данные календаря хранятся в базе, а Markdown используется для формирования ответов slash-команды.

## Возможности

* просмотр событий на сегодня;
* просмотр календаря текущей недели;
* просмотр собственных будущих событий;
* удалённая работа;
* отпуска;
* отгулы;
* больничные;
* встречи с указанием времени и названия;
* удаление собственных событий по ID;
* русские и английские команды;
* диапазоны дат с автоматическим переходом на следующий год;
* защита от пересекающихся статусов одного пользователя;
* проверка токена Loop;
* SQLite-хранилище;
* Markdown-представление календаря.

## Команды

### Просмотр календаря

```text
/cal today
/cal week
/cal mine
```

* `today` — события на сегодня;
* `week` — календарь команды на текущую неделю;
* `mine` — ваши будущие события вместе с их ID.

### Удалённая работа

```text
/cal remote today
/cal remote tomorrow
/cal remote 24.08
/cal remote 24.08..26.08
```

### Отпуск

```text
/cal vacation 01.09..14.09
```

### Отгул

```text
/cal off 28.08
```

### Больничный

```text
/cal sick today
/cal sick 24.08..26.08
```

### Встречи

```text
/cal meeting 25.08 14:00-15:00 "Редакционная планерка"
```

### Удаление события

```text
/cal delete 42
```

Удалять можно только собственные события.

ID своих событий можно посмотреть командой:

```text
/cal mine
```

### Справка

```text
/cal help
```

## Русские алиасы

Для основных команд поддерживаются русские варианты.

### Статусы

```text
remote      → удаленка, удалёнка
vacation    → отпуск
off         → отгул
sick        → больничный, болею
```

### Просмотр

```text
today       → сегодня
week        → неделя
mine        → мой, мои, я
```

### Встречи

```text
meeting     → встреча, собрание, совещание
```

### Удаление

```text
delete      → удалить, отменить, отмена
```

### Справка

```text
help        → помощь
```

Например:

```text
/cal удалёнка завтра
/cal отпуск 01.09-14.09
/cal больничный сегодня
/cal встреча 25.08 14:00-15:00 "Планерка"
/cal мои
/cal удалить 42
```

## Форматы дат

Поддерживаются относительные даты:

```text
today
tomorrow
сегодня
завтра
```

Календарные даты:

```text
25.08
25.08.2026
2026-08-25
```

Для даты без года используется текущий год.

Диапазоны можно задавать через:

```text
24.08..26.08
24.08-26.08
24.08–26.08
24.08—26.08
```

Если диапазон без указания года пересекает Новый год, конечная дата автоматически относится к следующему году. Например:

```text
/cal vacation 29.12..08.01
```

## Правила статусов

У одного пользователя не может быть двух пересекающихся статусов.

Например, если уже существует:

```text
/cal vacation 01.09..14.09
```

то добавить:

```text
/cal remote 10.09
```

не получится.

В ответ бот покажет ID конфликтующего события и предложит сначала удалить его:

```text
/cal delete <id>
```

Встречи не являются статусами и могут существовать одновременно со статусами.

## Установка

Проект использует Python 3.14 и [uv](https://docs.astral.sh/uv/).

Установите зависимости:

```bash
uv sync
```

Создайте локальный файл конфигурации:

```bash
cp .env.example .env
```

## Конфигурация

Пример `.env`:

```dotenv
LOOP_SLASH_TOKEN=your_token
DATABASE_URL=sqlite:///data/calendar.db
TIMEZONE=Europe/Moscow
```

### `LOOP_SLASH_TOKEN`

Секретный токен slash-команды Loop.

Обязательный параметр.

### `DATABASE_URL`

SQLAlchemy URL базы данных.

По умолчанию:

```text
sqlite:///data/calendar.db
```

При использовании SQLite необходимая директория создаётся автоматически при запуске приложения.

### `TIMEZONE`

Часовой пояс, используемый для определения текущей даты.

По умолчанию:

```text
Europe/Moscow
```

Используется стандартная база часовых поясов IANA.

## Настройка Loop

Создайте пользовательскую slash-команду с trigger:

```text
cal
```

и укажите POST endpoint:

```text
https://your-host.example/loop/command
```

Loop отправляет запрос как:

```text
application/x-www-form-urlencoded
```

Приложение ожидает как минимум:

```text
text
token
user_id
user_name
```

Также могут передаваться:

```text
channel_id
team_id
```

## Авторизация Loop

Приложение выполняет двойную проверку токена.

Токен должен присутствовать одновременно:

1. в form-поле `token`;
2. в HTTP-заголовке `Authorization`.

Поддерживаются оба варианта заголовка:

```text
Authorization: Token <token>
```

и:

```text
Authorization: Bearer <token>
```

Оба значения должны совпадать с:

```text
LOOP_SLASH_TOKEN
```

Сравнение токенов выполняется безопасным способом через `secrets.compare_digest()`.

## Хранение данных

Источник истины — база данных SQLite.

По умолчанию файл расположен здесь:

```text
data/calendar.db
```

В базе хранятся пользователи и события календаря.

Событие содержит, в зависимости от типа:

* владельца;
* тип события;
* начальную дату;
* конечную дату;
* время начала и окончания встречи;
* название встречи.

Файлы базы данных являются runtime-данными и исключены из Git.

## Markdown

Markdown используется как слой представления.

На его основе бот формирует:

* календарь на сегодня;
* недельную таблицу команды;
* список собственных будущих событий;
* список встреч;
* сообщения о создании и удалении событий;
* справку `/cal help`.

Markdown не является источником данных: вся информация каждый раз формируется на основе текущего состояния SQLite.
